### Test 4: メロディ + 伴奏 — 2026-08-21（初回）

**入力**: `tests/inputs/04_melody_accomp.mid`
- メロディ: C4 から1オクターブ上行するドレミファソラシド、velocity **110**、8分音符
- 伴奏: C3-E3-G3 の3和音、velocity **55**、4分音符 ×4

**変換結果**: 20音 / 最大同時4音 / pling 12 + harp 8 / 36 tick

**ユーザーの聴感（原文）**:

> 演奏して音がなった
> ドレミファソラシドが大きくぽんぽんと小さく聞こえた

**わかったこと**:

- ✅ **鳴った。** データパック方式・直線コリドー・テレポート駆動が実機で成立している
- ✅ **距離による音量制御が効いている。** メロディ（velocity 110）が大きく、
  伴奏（velocity 55）が小さく聞こえている。Test 4 が狙っていた
  「主旋律と伴奏の音量差」がそのまま出た
- ✅ 音程が上行して聞こえている（音階として認識できている）

**問題点**:

- ⚠ **強弱の差が誇張されている可能性が高い。** 原曲の velocity 110 と 55 は
  **−6 dB** の差だが、hyperchoron の velocity 変換が対数寄りで、
  NBS では 100 と 10 = **−20 dB** になっている。
  「大きく」と「小さく」の差が実際より大きく聞こえているはず
- ⚠ 「ぽんぽん」= 音が短く途切れて聞こえている。pling の減衰は −40 dB まで
  0.468 秒（9.4 tick）なので、8分音符（0.25秒 = 5 tick）では次の音が来る前に
  減衰しきらないはずだが、**アタックが立ちすぎている**可能性がある

**改善方法**:

| 何を | いつ |
|---|---|
| velocity 変換を線形寄りに直す（hyperchoron の出力を後段で補正する） | v4（編曲最適化器） |
| 距離減衰の式を実測で確定させ、velocity → 距離の写像を較正する | v1（測定リグ） |
| `ATTACK` / `TAIL` テンプレートでアタックと余韻を整える | v4 |

**未確認**（次に鳴らすときに聞いてほしい）:

- テンポが原曲と合っているか
- `snare` に使っている `heavy_core` がスネアの音になるか（Test 5）
- 3ブロック/tick のテレポート移動が酔わないか

### 実楽曲（Test 10 相当）: 真っ黒ナイト・オブ・ナイツ — 2026-08-21

**入力**: https://www.youtube.com/watch?v=2R_LwO3Zi7s （RIN__ / 3:45）の先頭20秒
**経路**: 音源 → hyperchoron（DeEcho → BS-RoFormer → HTDemucs-ft → DrumSep → CQT採譜）→ NBS → 配置 → データパック

**変換結果**:

```
402 tick (20.1秒) / 3,787音 / 最大同時発音 57 / 7,574ブロック / 廊下 1,206ブロック
iron_xylophone 2087, harp 902, guitar 727, bass 66, cow_bell 5
```

**ユーザーの聴感（原文）**:

> 今オーディオそのままだね
> 聴覚パレイドリアみたい

**これが v0 の到達点であり、限界**。以降の作業はここを出発点にする。

**何が起きているか**:

3,787音 / 20秒 = **毎秒190音**。これは楽譜ではなく、
**スペクトログラムを音符ブロックで描いたもの**。

hyperchoron の音声パス（`pcm.py` の `decompose_stem`）は
``librosa.hybrid_cqt`` のスペクトルから **1フレームあたり最大32本のピーク**を
そのまま音符にする。基音と倍音を区別しないので、1つの音が何本もの音符になる。

だから「元の曲が見える気がする」が音楽になっていない。
**聴覚パレイドリア** ＝ ノイズの中に元の形を脳が補完している状態、というのは
現象として正確な言い方。

**改善方法**:

| 何を | どう | いつ |
|---|---|---|
| 倍音を基音に畳む | CQT ピークから倍音列を検出して基音1本にまとめる | v5（採譜補正） |
| 音数を musical に間引く | 「聞こえるべき音」を選ぶ。毎秒190音は人間の編曲では出てこない | v4（編曲最適化） |
| 深層学習の採譜に替える | Basic Pitch / YourMT3+ は音符単位で出すので倍音を吐かない | v5 |
| 良し悪しを数値で測れるようにする | オフラインレンダラ + 目的関数。これが無いと改善したか分からない | **v2 / v3 ← 次はここ** |

**先に v2（レンダラ）をやる理由**: 上の3つはどれも「やってみて良くなったか」を
判定できないと進められない。ゲームを起動せずに音を作って数値で比べられる状態が先。

#### v2 のレンダラで数値化した結果（2026-08-21）

`mcnb render` で同じ配置を合成し、原曲と比べた（どれも 1.0 が一致）:

| 指標 | 値 | 読み方 |
|---|---:|---|
| 和声 (chroma) | **+0.824** | ピッチクラスの分布はよく合っている |
| 強弱 (loudness) | **+0.911** | 音量の動きはよく合っている |
| リズム (onset) | **+0.342** | **立ち上がりが合っていない** |
| 明るさ (centroid) | **+0.067** | **音色の動きが全く追えていない** |

帯域エネルギー比 (MC版 / 原曲):

| 帯域 | 比 | |
|---|---:|---|
| 低域 (0–128 Hz) | **0.438** | **足りない** |
| 中低域 (128–512 Hz) | **1.897** | 出すぎ |
| 中高域 (512–2048 Hz) | 0.747 | |
| 高域 (2048 Hz–) | 1.098 | |

**「聴覚パレイドリア」の正体がこれ。**
和声（0.82）と音量（0.91）は合っているのに、
**リズム（0.34）と音色（0.07）が合っていない**。
脳は和声とダイナミクスの手がかりで曲を認識できるが、
実際には演奏されていない。

さらに具体的な欠陥が2つ:

1. **低音が半分以下しか出ていない。** bass は 3,787 音中 66 音しかない。
   音符ブロックは F♯1 = 46.25 Hz まで出せるので、原理的な制約ではなく
   採譜が低音を拾えていない
2. **エネルギーが 128–512 Hz に偏っている**（1.9倍）。
   CQT のピーク拾いが中低域の倍音を大量に音符にしているため

スペクトログラムでも、原曲にある**横線（持続した音）が MC 版には無い**。
音符ブロックは 0.5 秒で減衰しきるのに再発音していないため。

**v3 での目的関数はこの4指標を土台にする。** ただし単純な重み付き和ではなく、
onset と centroid が低いままなら chroma が高くても駄目、という形にする必要がある。

## v4 の最初の実験: 音を減らすと何が起きるか — 2026-08-21

`arrange.py` に編曲の変換を4つ作って、真っ黒ナイト・オブ・ナイツ20秒で測った。

### わかったこと1: 音数は3割に減らせる。和声は落ちない

| | 音数 | 和声 | リズム | 同時発音で落ちた音 |
|---|---:|---:|---:|---:|
| 素通し | 3,787 | +0.824 | +0.342 | 140 |
| 編曲あり | 1,159 | +0.811 | +0.305 | **0** |

倍音を畳み、同音の重複を消し、サステインを実測の減衰時間に合わせて間引いた。
**和声はほぼ落ちない**（0.824 → 0.811）。バニラの247上限で落ちていた140音も消えた。

### わかったこと2: 「雑音らしさ」は音数では動かない

雑音らしさ（spectral flatness）を測ると:

| | flatness |
|---|---:|
| **音符ブロックの素の音** | **0.0003〜0.07** |
| Test10 音階（重ならない73音） | 0.0497 |
| Test4 メロ+伴奏（重なる20音） | 0.1676 |
| 原曲（Black MIDI） | 0.1279 |
| knights20 素通し 3,787音 | 0.1884 |
| knights20 606音まで削減 | **0.1880** |
| knights20 同時22音まで削減 | **0.1880** |

**音を1/6に減らしても、同時発音を247→22にしても、雑音らしさは動かない。**

音符ブロックの素の音は全く雑音ではない（0.0003〜0.07）のに、
2音以上重ねた時点で 0.17 付近まで跳ね上がる。
つまり **flatness は「音楽的かどうか」ではなく「和音かどうか」を測っている**。
この指標では編曲の良し悪しは判定できない。

### わかったこと3: 使えた指標は「音程のはっきりさ」

chroma のピークの立ち具合（1フレームの中で最大のピッチクラスが占める割合）:

| 同時発音の上限 | 音数 | 音程のはっきりさ |
|---:|---:|---:|
| 素通し | 3,787 | 0.215 |
| 48 | 1,153 | 0.207 |
| 24 | 917 | 0.215 |
| 12 | 592 | **0.235** |
| 6 | 340 | 0.279 |
| **（原曲）** | | **0.251** |

**単調に改善し、同時8〜12あたりで原曲に一致する。**

### いま詰まっているところ: 指標が互いに矛盾する

- 音を減らすと **音程のはっきりさ**は改善する（0.215 → 0.279）
- 同時に **リズム**は悪化する（0.342 → 0.226）
- **和声**もわずかに落ちる（0.824 → 0.748）

リズム指標が悪化するのは当然で、**原曲が Black MIDI だから**。
原曲の onset は極端に密なので、それに相関させたければ音を撒くほうが有利になる。

つまり **「原曲の音声との相関」を目的関数にすると、パレイドリアが最適解になる**。
これは調査時に警告した「単一指標に最適化すると音楽的に不自然になる」の実例。

### 次にやるべきこと

目的関数を「原曲との相関」だけで作るのをやめる。要るのは:

1. **音符ブロックとして成立しているか**の指標（音程のはっきりさ系）
2. **原曲の骨格を保てているか**の指標（和声・主旋律）
3. その2つのバランスを、**人間の耳で較正する**

聴き比べ用の音を `out/聴き比べ/` に出した。
どれが一番「曲に聞こえるか」を聞いて、そこから重みを決める。

## 聴き比べの結果 — 2026-08-21

同時発音の上限を振って4種類つくり、どれが一番「曲に聞こえるか」を聞いた。

| | 音数 | 同時最大 | 音程のはっきりさ | リズム相関 |
|---|---:|---:|---:|---:|
| **1_素通し（現状）** | **3,787** | **247** | 0.215 | **+0.342** |
| 2_重なり上限24 | 917 | 66 | 0.215 | +0.308 |
| 3_重なり上限12 | 592 | 37 | 0.235 | +0.293 |
| 4_重なり上限6 | 340 | 22 | 0.279 | +0.226 |
| （原曲） | | | 0.251 | |

**ユーザーの選択（原文）**:

> 1_素通し(現状).wavかな

### これは仮説の否定

こちらは「毎秒190音は多すぎる、人間の編曲ならもっと少ない」と考えて
削る方向で作った。**その方向は間違いだった。**

- 音程のはっきりさは削るほど改善し、上限12で原曲に一致した。**それでも耳は素通しを選んだ**
- リズム相関は削るほど悪化した。**こちらの指標のほうが耳と一致していた**

原曲が Black MIDI で本当に音が詰まっているので、
**密度を落とすことは原曲から離れること**だった。

### ということは、パレイドリアの原因は音数ではない

残る候補:

1. **音が「正しい音」でない。** CQT のピーク拾いは基音も倍音もノイズも
   区別せず音符にする。音数が同じでも中身が違う
2. **アタックが揃っていない。** onset 相関 0.342 は密度のわりに低い
3. **音色が追えていない。** centroid 相関 0.067

**次は削るのをやめて、採譜の中身を良くする方向に切り替える。**
深層学習の採譜（Basic Pitch / YourMT3+）に差し替えて、
同じ密度でも「音符」として出てくるとどうなるかを見る。

なお素通しは**バニラの247上限で140音が落ちている**。
RSLS を入れてあるので、全部鳴らす版も作れる。まずそれを聴いてもらう。

## Minecraft 26.2 の保存形式の変更

ワールド生成の設定を確認していて見つけた。**`level.dat` から出ている**:

| 何 | 26.2 での場所 |
|---|---|
| ゲームルール | `data/minecraft/game_rules.dat`（`minecraft:` 名前空間つきのキー） |
| 地形生成の設定 | `data/minecraft/world_gen_settings.dat` |
| 天候 | `data/minecraft/weather.dat` |
| 時刻 | `data/minecraft/world_clocks.dat` |

`level.dat` の `Data` に残っているのは
`LevelName` / `GameType` / `allowCommands` / `SpawnX,Y,Z` / `DataVersion` など少数。
**`GameRules` と `WorldGenSettings` を level.dat から読む既存ツールは 26.2 で動かない。**
